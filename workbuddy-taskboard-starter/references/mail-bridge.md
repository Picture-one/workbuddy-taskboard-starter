# 邮件双向桥：发提醒到微信，回邮件即完成任务

**目标**：定时把今日任务清单推到你的手机，你直接回复就能把结果写回本地看板。

**为什么用邮件？** 因为它是**成本 ¥0 且不需要公网入口**的方案：

| 环节 | 需要什么 | 结果 |
|---|---|---|
| 上行（发提醒） | SMTP 出站连接 | 不需要公网入口、不需要域名 |
| 下行（收回复） | IMAP 出站连接 | 不需要公网入口、不需要域名、不需要备案、不需要服务器 |

两条都是**本机主动发起的出站连接**，所以什么门槛都不用跨。

---

## 决策记录：为什么不用企业微信做双向

如果你也在考虑「企业微信机器人 + 回调」这条更"正规"的路，先看这四条，能省你几天：

| # | 结论 | 说明 |
|---|---|---|
| 1 | **群机器人只能单向推送** | 官方明确不支持消息回调。你在群里打 `c1`，系统收不到任何东西——这是**平台限制，不是配置问题**，怎么调都调不通 |
| 2 | **群机器人的消息到不了个人微信** | 它只到企业微信 App / 群，不是你的微信 |
| 3 | **可信 IP 要人工配、而家庭宽带 IP 会变** | 意味着它只能当"提醒"，不能当"稳定的服务端" |
| 4 | **应用回调要求已备案域名，且域名主体须与企业主体一致** | 家庭环境基本走不通 |

**结论**：企业微信只保留为**单向兜底提醒通道**（`pushWecom: true` 时启用），
**永远不要指望它能收到回复**。所有回复都必须走邮件。

> `mailer.py` 已在企业微信推送内容的底部自动附加这条警告，防止未来的你（或别人）在群里白打指令。

## 三条设计约束（改代码前必读）

### 1. 对邮箱严格只读，绝不改动你的邮件状态

* `INBOX` 以 `readonly` 方式打开 → 协议层面禁止改 flag
* 取正文用 `BODY.PEEK[]` → 而 `BODY[]` / `RFC822` 会**隐式把邮件标记为已读**
* 全程不发送任何 `STORE` 指令
* 去重靠 `state\processed.json` 里的 Message-ID，**不依赖「已读/未读」状态**

### 2. 只处理「回复」类邮件

判定条件（需**同时**满足）：主题含 `[任务面板]` **且** 以回复前缀开头
（`Re:` / `Re：` / `回复：` / `答复:`）。

两个原因：

* 我们自己发出的清单/回执邮件会**回流到同一个收件箱**，而清单正文里印着指令示例行
  （`r1 新内容`、`+ 新任务`、`复盘 内容`）—— 不拦住会被误执行成改标题、凭空加任务
* 收件箱可能有几千封历史邮件，**绝不能全量扫描**

**宁可漏执行，也不能误执行。** 所以回复必须用邮件客户端的「回复」功能，不能新建邮件手打主题。

### 3. 只看最近 N 天且发件人是自己

由 `lookbackDays`（默认 7）控制，IMAP 侧用 `SINCE + FROM` 过滤，不拉全量。

## 一、准备两样东西

### 1. QQ 邮箱的 SMTP/IMAP 授权码

> ⚠️ 要用**授权码**，不是 QQ 登录密码。

1. 电脑浏览器打开 <https://mail.qq.com/> 登录你的 QQ 邮箱
2. 顶部「设置」→「账号」
3. 找到 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务」** 一栏
4. 把 **IMAP/SMTP 服务**打开 → 按提示用手机发一条短信 → **生成授权码**
5. 复制那串 16 位授权码

> 🔒 授权码**等同于邮箱密码**。它只应存在于本机的 `config.json` 里。
> 本项目的 `.gitignore` 已把 `config.json` 排除，仓库里只有 `config.example.json`。

### 2. 微信里开启「QQ邮箱提醒」

> ⚠️ 这一步没做好，整条上行链路会**彻底静默** —— 邮件照发、你什么也收不到，而且没有任何提示。
> 下面每一条都是实测/官方文档确认过的失败原因，按顺序核。

**① 先确认入口在不在**

微信 → 我 → 设置 → 通用 → **辅助功能** → 找 **「QQ邮箱提醒」**
（快捷方式：微信顶部搜索框直接搜「QQ邮箱提醒」，一步直达）

**入口根本不显示**，说明这个微信号**还没绑定 QQ 号**：
微信 → 我 → 设置 → 账号与安全 → 更多安全设置 → **绑定 QQ 号** → 再回头找。

**② 进去之后必须打开「接收邮件提醒」**

| 开关 | 要求 |
|---|---|
| **接收邮件提醒** | **必须打开**，否则绑定成功也不推 |
| 置顶此功能 | 建议打开，否则容易被别的服务消息淹掉 |

**③ 提醒出现在「服务通知」里，不是聊天列表**

这是最容易误判的一点：微信的 QQ邮箱提醒**不生成独立聊天窗口**，而是作为一条服务消息出现在
**微信 → 服务通知**。翻聊天列表是找不到的。

**④ 杀手开关：QQ邮箱 App 里的「仅在QQ邮箱客户端提醒」**

如果你的手机装了 QQ邮箱 App，且它开了 **设置 → 新邮件提醒 → 仅在QQ邮箱客户端提醒**，
**微信的提醒会被完全抑制**。去把这个开关**关掉**。

**⑤ 绑定会失效，要会重新绑**

以下三种情况会让绑定失效（之后邮件照收，但微信不提醒）：改过 QQ 邮箱密码或独立密码 /
在 QQ 邮箱「设备管理」里解除了绑定 / 在微信里解除了 QQ 邮箱绑定。
处理办法：重新走一遍 ①②。

## 二、填配置

先复制模板：

```bat
copy config.example.json config.json
```

再编辑 `config.json`：

```json
{
  "email": "你的QQ号@qq.com",
  "authCode": "刚才生成的16位授权码",
  "smtpHost": "smtp.qq.com",
  "smtpPort": 465,
  "imapHost": "imap.qq.com",
  "imapPort": 993,
  "taskboardProjectId": "wb-demo",
  "pollIntervalSec": 60,
  "lookbackDays": 7,
  "wecomWebhookUrl": "",
  "pushWecom": false,
  "ackByEmail": true
}
```

| 字段 | 说明 |
|---|---|
| `email` / `authCode` | 你的 QQ 邮箱与 16 位授权码 |
| `smtpHost` / `smtpPort` / `imapHost` / `imapPort` | 默认是 QQ 邮箱；换别家邮箱就改这里 |
| `taskboardProjectId` | 把回复回写到哪个项目下的任务 |
| `pollIntervalSec` | 常驻轮询间隔（秒） |
| `lookbackDays` | 只扫最近几天的回复 |
| `wecomWebhookUrl` / `pushWecom` | **可选单向兜底**，留空即关闭。⚠️ 用它收不到回复 |
| `ackByEmail` | 回写成功后是否给你回一封回执邮件 |

## 三、跑通三步

```bat
:: 第 1 步：发一封测试邮件，看微信是否弹出提醒
send-test.cmd

:: 第 2 步（关键）：在微信里「回复」那封邮件，正文只写一行  ping
:: 然后跑一轮轮询，看能不能读到你的回复
poll-once.cmd

:: 第 3 步：都通了之后，日常这么用
send-daily.cmd        发今日任务清单
start-poller.cmd      常驻，每 pollIntervalSec 自动回写一次
```

第 2 步成功的话，`poll-once.cmd` 会打印 `pong —— 下行链路通了`，并且你会收到一封「回执」邮件
（说明发信也正常）。

## 四、回复指令表

**回复的渠道只有邮件这一条**：在微信「服务通知」里找到那封清单邮件的提醒 → 直接回复；
或用 QQ邮箱 App / 网页版的「回复」功能。

**推荐直接说人话**（最不容易记错）：

| 你写 | 效果 |
|---|---|
| `把1、2项标记为已完成` | 把第 1、2 项标记为已完成 |
| `1和2完成` / `完成 1 2` / `第1项做完了` / `1 2 都完成` | 同上，说法随意 |
| `done 1、2` | 同上（英文也可以） |

也支持简写代号：

| 你写 | 效果 |
|---|---|
| `c1 c2` | 把第 1、2 项标记为已完成 |
| `c1、c3` / `c 1, 2` / `c:1 3` | 同上，分隔符随便用 |
| `done ABC-1` | 直接用任务编号标记完成 |
| `r1 新的标题` | 把第 1 项的标题换成新内容 |
| `+ 补充材料 S2` | 追加一条新任务 |
| `复盘 今天……` | 写入当日复盘（存到 `state\review-日期.md`） |
| `ping` | 只测链路，不动作 |

> **自然语言只开「标记完成」这一个动作。** 改标题（`r1`）、新增任务（`+`）必须用严格语法 ——
> 这类会改动/新增数据的动作，宁可漏执行也不能被一句随口的话误触发。
>
> 而且只有当整句话「除了数字和完成类词之外没别的内容」时才会执行：
> 所以 `完成了3篇论文的阅读` **不会**被误认成「勾第 3 项」。
>
> **重复回复是安全的**：已完成的任务会回「已是完成状态（重复的回复已忽略）」，不会报错。

> **必须用「回复」功能**（这样主题才带 `Re:`，程序才会处理）。
> 正文只保留你自己写的那一行；引用的原文程序会自动剥离，但删掉最保险。

> ⚠️ **不要在企业微信的群里回复** —— 那是单向通道，收不到任何东西（见上面的决策记录）。

## 五、看板服务自愈（按需启动，用完即收）

看板服务如果是由前台进程衍生的，**会话结束可能被一起回收**。而每日定时的推送是无人值守跑的。

所以每次需要访问看板前先自检，不在就临时拉起一个：

```
[自愈] 看板服务未响应，临时拉起 ...
[自愈] 已就绪（本次运行结束后自动停）。
```

* **只回收自己拉起的那个实例** —— 你手动 `start-taskboard.cmd` 开的常驻服务不会被碰
* 脚本正常退出、报错退出、Ctrl+C，都会经由 `atexit` 关掉临时实例
* 启动失败会打印 `server.log` 路径，并且会检测「起来后立刻退出」这种情况

要看板 UI 时仍然手动开：`start-taskboard.cmd`。

## 六、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `SMTP 登录失败` | 填了登录密码而不是授权码 | 重新生成授权码 |
| `IMAP 登录失败` | 邮箱没开 IMAP 服务 | 见第一节第 1 步 |
| 邮件发了，微信没提醒 | 微信「QQ邮箱提醒」没开 / 绑定失效 | 见第一节第 2 步的 ①②④⑤ |
| 聊天列表里找不到提醒 | 提醒在「**服务通知**」里 | 微信 → 服务通知 |
| 装了 QQ邮箱 App 后微信就不提醒了 | App 里开了「仅在QQ邮箱客户端提醒」 | 关掉该开关 |
| 邮件进了垃圾箱 | 被误判 | 把发信地址加白名单 |
| `poll-once` 读到 0 封 | 回复主题缺 `Re:` 前缀被跳过；或该邮件已在去重表里 | 用「回复」功能而非新建邮件；重测可删 `state\processed.json` |
| **在企业微信群里回复了 `c1`，没反应** | **群机器人只能单向推送** | 改在微信「服务通知」里回复邮件 |
| 报 `找不到对应任务` | 摘要邮件已被清理，编号映射丢失 | 收到今日清单后尽快回复 |
| 报 `SERVICE_UNAVAILABLE` / `Cannot reach taskboard` | 看板服务被回收了 | 不用管，自愈机制会拉起 |
| 担心轮询把邮件标成已读 | **不会**（`readonly` + `BODY.PEEK[]`，不发 STORE） | 见「设计约束」 |

### ⚠️ 通用代理坑（值得所有写本机 HTTP 探测的人记住）

如果你的机器上设了 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量（很多公司网络或代理软件会设），
**Python 的 `urllib` 会把对 `127.0.0.1` 的请求也送进代理**。

后果：健康检查拿到的是**代理返回的 502**，而不是「连不上」—— 于是**活着的服务被误判成离线**，
离线的又会被误判成别的问题。

本项目所有本机 HTTP 请求都显式绕过代理：

```python
NO_PROXY_OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

同时给 `taskctl` 子进程剥离代理变量并设 `NO_PROXY=127.0.0.1,localhost`。

> 排查提示：在这类机器上做任何「探测本机端口」的代码，**别直接用裸 `urlopen`**。
> 命令行同理 —— `curl --noproxy '*'`。

## 七、文件清单

```
mail-bridge\
├── config.example.json  模板（入库）
├── config.json          ⚠️ 存授权码，已被 .gitignore 排除
├── common.py            配置 / 看板读写 / 状态文件（纯标准库）
├── mailer.py            上行：发测试邮件或今日清单
├── poller.py            下行：IMAP 拉回复 → 解析 → 回写看板
├── send-test.cmd        发测试邮件
├── send-daily.cmd       发今日清单
├── poll-once.cmd        跑一轮轮询（测试）
├── start-poller.cmd     常驻轮询（日常）
└── state\               运行态，不入库
    ├── digest-YYYY-MM-DD.json   编号 → 任务 的映射
    ├── processed.json           已处理的邮件 Message-ID
    └── review-YYYY-MM-DD.md     复盘记录
```

**依赖**：仅 Python 3 标准库（`smtplib` / `imaplib` / `email` / `json`），无需 pip install，无需 npm。
**回写途径**：调用看板的 CLI（`cli\taskctl.mjs`），本机看板服务需在运行。
